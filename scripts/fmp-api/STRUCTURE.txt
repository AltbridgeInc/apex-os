DATA FLOW ARCHITECTURE
----------------------

User/Agent
    ↓
fmp-fetch.sh (Master Orchestrator)
    ↓
Category Router (company/financials/quotes/earnings/analyst/bulk)
    ↓
Specialized Fetcher (fetch-*.sh)
    ↓
utils.sh (API call, error handling, validation)
    ↓
config.sh (load API key, settings)
    ↓
FMP API (https://financialmodelingprep.com/api)
    ↓
Response Processing (validate, parse, save)
    ↓
File Storage (fmp-data/*/) + JSON Response
    ↓
User/Agent

ERROR HANDLING FLOW
--------------------

API Call
   ↓
Validation (symbol, params)
   ↓ (fail)
   └──→ Return JSON error
   ↓ (pass)
Rate Limit Check
   ↓ (approaching limit)
   ├──→ Sleep 10s, continue
   ↓
HTTP Request (curl with timeout)
   ↓ (network error)
   ├──→ Retry (up to 3 times, exponential backoff)
   ↓ (HTTP error)
   ├──→ 429/500/503: Retry
   ├──→ 400/401/403/404: Return error
   ↓ (200 OK)
Validate JSON Response
   ↓ (invalid)
   ├──→ Return JSON error
   ↓ (valid)
Save to File
   ↓
Return Success JSON

RATE LIMITING STRATEGY
---------------------

1. Track requests in /tmp/fmp_rate_YYYYMMDD_HHMM.txt
2. Count requests in current minute window
3. If approaching limit (240/250):
   - Sleep 10 seconds
   - Clear old tracking files
   - Start new minute window
4. Record each request with timestamp
5. Auto-cleanup old tracking files (>2 minutes old)


RETRY STRATEGY
--------------

Retryable Errors: 429 (rate limit), 500 (server error), 503 (unavailable)
Non-Retryable: 400 (bad request), 401 (auth), 403 (forbidden), 404 (not found)

Retry Logic:
  Attempt 1: Immediate
  Attempt 2: 2^1 = 2 second delay
  Attempt 3: 2^2 = 4 second delay
  Attempt 4: 2^3 = 8 second delay
  
  After 3 retries: Return error

-----------------------

1. Environment variables (highest priority)

4. .env file in user home
5. Default values in config.sh (lowest priority)
